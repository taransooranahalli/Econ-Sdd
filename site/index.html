02 / Specification-driven development

Make the reasoning
reviewable.

The spec owns the behavior. The implementation stays small enough to check against it.

  1. 01

    Define the contract

    Inputs, units, timing, valid ranges, rounding, edge cases, and numbered acceptance criteria.

    Product specification ↗
  2. 02

    Implement a bounded slice

    Pure Python calculations stay separate from the web UI, file adapters, and account storage.

    Architecture decisions ↗
  3. 03

    Check independently

    Cash-flow sums, exact fractions, integer currency units, boundaries, and useful invariants.

    Read the tests ↗
  4. 04

    Record what passed

    Report actual verification, unresolved limits, model versions, and the next milestone.
